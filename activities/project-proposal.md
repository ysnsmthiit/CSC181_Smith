### Selected problem

\[Identify the problem your team selected.\]&nbsp;

Our team chose the 3rd candidate problem “Campus event announcements are scattered across platforms, making it difficult for organizations to reach students and resulting in low event registrations.”&nbsp;

### Selection rationale

\[Explain your choice in 3–5 sentences. Address relevance, stakeholder access, team readiness, semester feasibility, and why the other candidates were not selected.\]&nbsp;

We selected the Centralized Campus Event Announcement Platform because university event updates are currently fragmented across individual social media pages, and as MSU-IIT students, our team has direct daily access to both student organization leaders and general attendees for feedback. Among the shortlisted ideas, this project presents the lowest operational friction for our team's current skill set, allowing us to build a working web app within our two-month constraint. By focusing on core features like event listings, organization profiles, countdown banners, and student feedback tools, we can reliably deliver and demonstrate a functional prototype before the semester ends. In contrast, the public transit guide was rejected due to time-consuming route data gathering, and the fee tracker was passed over because an event portal delivers broad impact to the entire student body rather than benefiting only department officers.

## 3\. Preliminary Project Proposal

### Working project title

**CATS App: A Campus Organization and Events Platform for MSU-IIT**&nbsp;

### Problem statement

\[Write 100–150 words. Identify the affected users, context, current approach, difficulty, consequences, desired improvement, and assumptions requiring validation.\]

MSU-IIT Students frequently miss relevant campus events, workshops and activities because announcements are fragmented across different Facebook pages, groups and physical posters. Student organizations currently rely on manual cross-posting and group chat announcements, while students must passively monitor multiple channels leading to announcement fatigue. This fragmentation of information limits student reach and prevents students from fully engaging in both co-curricular and extracurricular opportunities that enriches the overall student experience. The project aims to improve campus event discovery and increase awareness of student organization activities within MSU-IIT. The team still needs to confirm whether students prefer a centralized platform over existing social media channels and whether student organizations are willing to use the platform to promote their events.&nbsp;

### Proposed solution

CATS App is a centralized web application for MSU-IIT students to discover, explore, and connect with campus organizations. It will showcase each organization’s profile, activities, and upcoming events, with features such as countdown banners, and feedback tools. Other features like pooling may also be added if time permits. By giving organizations a dedicated space to share their identity and engage with students, the app aims to increase awareness and encourage participation in campus activities.

## 5\. Initial Scope

### Intended users and setting

The intended users include:

1. **MSU-IIT Students:** Students who want to explore campus organizations, learn about their activities, and discover upcoming events, including those open to non-members.  
2. **KASAMA, College Executive Councils (SCs), Department Societies, Student Organizations and Officers:** Organizations that want to showcase their identity, share announcements, and promote their activities and events.

The system will operate as a web application accessible through web browsers on computers and mobile devices. It will serve as a centralized space for organization profiles and event announcements, and promote their activities and events.

### In-scope capabilities

\[Describe 3–5 specific capabilities as actions users can perform.\]

1. A student can create a profile with a preset name and photo based on their MyIIT account. An organization officer can create and edit their org’s profile and post events  
2. A student can browse and search organization profiles to see what each org does and how to join  
3. A student can see a list of upcoming events, with a countdown banner on events that are coming soon.  
4. A student can send feedback on an event after it happens, and the officer can read it.  
5. Students can vote on polls posted by organizations. This includes a “Going” or “Not Going” feature that allows users to indicate whether they plan to attend an event&nbsp;

### Out-of-scope capabilities

\[Identify at least three features, integrations, services, or settings excluded from this semester's version.\]

1. A student can create a personalized profile (profile picture, username and short 10-15 word description)  
2. A student can filter events by date or type, so they only see what’s relevant to them.  
3. Automatic cross-posting to Facebook or other social media.  
4. In-App Event registration

### Expected deliverables

\[List the planned outputs, such as a working prototype, documentation, and testing evidence.\]

* Working Prototype \- a working web-application prototype with the functionality and core features as listed in the in-scope capabilities  
* Testing Evidence \- feedback gathered from select students and organization officers to evaluate the app’s usability and functionality  
* Project Documentation \- a user guide documentation that helps guide students and organization officers through the application  
* Source code repository \- a Github repository containing the project’s source code and instructions for setting up and running the project

## 6\. Review and Next Steps

### Change made after reviewing the proposal

- Before review: A messaging feature as well as profile customization was included in the original scope.  
- After review: Added features (“Going”, post reactions) to in-scope capabilities. Removed messaging features, moved profile customization to out of scope.  
- Reason: The added features improve the usefulness of the web app and promote user engagement. We decided that the messaging feature and profile customization was not feasible given the time limit and our team’s capabilities.

### Biggest remaining risk

The tight semester timeline (8–10 weeks). If building the backend or core features takes longer than expected, we won't have enough time left to conduct proper usability testing with real students and officers before the project deadline.

### Three unanswered questions

1. Specifications and tech stack to use in implementing the project  
2. How to integrate Gmail connectivity and validate that it comes from the g.msuiit.edu.ph domain  
3. How many weeks/days do we need to reserve for user testing and fixing bugs before final submission?
